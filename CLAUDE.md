# Claude Arcs

Nix flake that ships Claude Code workflow as a **plugin**. Invoked remotely via `nix run github:bugeats/claude --refresh` — no local clone required. The default package (`claude-arcs`) is a one-line launcher: `exec claude --plugin-dir <plugin> --settings <plugin>/settings.json`, where the plugin is the built derivation (`packages.plugin`). Nothing is written to `~/.claude/`; everything resolves from the immutable Nix store path. Multiple concurrent sessions on one host share the same store path safely.

This is a shared distribution used by teammates and a growing circle of users, not a single-user dotfiles repo. Changes here affect everyone on next launch.

**Everything the plugin says to the model is opt-in.** Guidance ships as two output styles selected in `/config`: `arcs:manual` carries the Compression Principle, the working contract, and context guidance; `arcs:auto` adds the arc workflow and its automatic triggers. With no style selected the session is vanilla Claude Code with the arcs skills available but never self-invoked. Claude Code keys plugin styles as `<plugin>:<name>`; the bare name does not resolve.

This file is project instructions for *this repo only*. The shipped prose lives in `prompts/`.

## Architecture

```
flake.nix                    # packages.plugin builds the plugin dir; default = claude-arcs launcher
.claude-plugin/plugin.json   # plugin manifest (name="arcs", semver, author, …)
hooks/hooks.json             # plugin-scope hook registrations (paths via ${CLAUDE_PLUGIN_ROOT})
settings.json                # passed via --settings; statusLine path baked at build + permissions
prompts/{containment,arcs}.md  # style bodies; flake splices them into output-styles/{manual,auto}.md at build
skills/<name>/SKILL.md       # auto-discovered by the plugin loader
style/<lang>.md              # language review criteria, read during /checkpoint Step 1
hooks/{nix-format,nix-guardian,rust-format}.sh   # writeShellApplication bodies, invoked from hooks.json
tools/{checkpoint-range,nix-status}.sh            # writeShellApplication bodies, invoked via ${CLAUDE_PLUGIN_ROOT}/tools/
statusline.py                # invoked from settings.json; shebang patched at build
```

The `.mcp.json` (rust-analyzer) is generated by the flake, not checked in: a source-tree copy would load as a project-scope server in every session developing this repo. Plugin content references its own files via `${CLAUDE_PLUGIN_ROOT}`; everything else is pinned to store paths at build, so the launcher exports nothing. See [docs/launcher.md](docs/launcher.md) for the mechanics and unmanaged state, [docs/dependencies.md](docs/dependencies.md) for runtime inputs.

## Usage

Launch (from any shell — no local clone required):

```
nix run github:bugeats/claude --refresh
```

Validate plugin changes locally (the plugin is the built derivation, not the source tree):

```
nix build .#plugin
claude plugin validate result
claude --plugin-dir result plugin details arcs
```

Skills (inside a Claude session, targeting the project flake):

```
/nix                           # show nix skill usage
/nix build [target]            # nix build [.#target] --print-build-logs (background agent)
/nix run [app]                 # nix run [.#app] (synchronous)
/nix status                    # show active nix builds and sandbox dirs
```

## Current Focus

**OPTN — opt-in via output styles.** Neither style sets `force-for-plugin`. Prose revision of `prompts/` is underway: `containment.md` has had its first pass (Vocabulary and Tools sections dropped as guidance that never stuck in practice; slug rule now names the forbidden `SLUG-3.a1` shape). `arcs.md` and the skill bodies namespace every self-invocation as `/arcs:<skill>`; the prose itself needed no content change.

- **OPTN-2** Interactive confirmation outstanding: fresh launch shows both styles in `/config`; selecting `arcs:auto` yields automatic checkpoints, selecting nothing yields none. Headless selection via `--settings '{"outputStyle":"arcs:auto"}'` is confirmed. Nix conventions now live in the `/nix` skill body, so they reach the model only on invocation; revisit if flake discipline slips in non-arcs sessions.
- **OPTN-5** Mid-session style switching: an `outputStyle` settings change does not rebuild the system prompt within a turn. Whether it applies on the next user turn or only after `/clear` is unknown; document the answer in docs/launcher.md once observed.

PostToolUse hooks are confirmed firing in real use; statusline rendering and skill resolution under `${CLAUDE_PLUGIN_ROOT}` still need verification on a fresh `nix run --refresh`.

Three arcs ship: `/checkpoint` (Minor), `/negentropy` (Major), `/shipit` (Greater). `/negentropy` Phase 2 includes a runtime-entropy lens alongside the Compression Principle — owned in-tree rather than delegating to `/simplify`, since fanning out three review agents per minor arc would discourage frequent checkpoints.

`statusline.py` resolves `tools/checkpoint-range.sh` via `__file__`-relative lookup so the gauge and `/negentropy` rebase share one algorithm. The walk is bounded at the mainline merge-base so published commits never enter a rebase range; the checked-out branch is skipped as a mainline candidate so local-only repos committing on `main` still see their own range. The script wraps its body in a top-level guard, appends tracebacks to `~/.claude/statusline.log`, and always exits 0 — Claude Code suppresses the status line after repeated failures and only retries on restart.

Shipped defaults in `settings.json`: `permissions.defaultMode: "acceptEdits"`, `remoteControlAtStartup: true`, no `model` pin, and `attribution` disabled so the harness adds no Co-Authored-By trailer, PR footer, or session link (`includeCoAuthoredBy` is the deprecated predecessor key). `statusLine.command` is an absolute store path substituted at build.

`prompts/` is a parallel work surface — the shipped guidance itself. Tightening shipped guidance is fair game at any checkpoint.

Language-specific style is tiered by cost-of-late-detection: mechanical rules → PostToolUse hooks (edit time); surface judgment → `style/<lang>.md` read during `/checkpoint` Step 1 (arc close, deliberately withheld from generation time — review compliance beats generation compliance); structural rules → Universal Code Style in `prompts/containment.md` (generation time, must stay tiny). `style/rust.md` seeds the middle tier; add languages by file drop, no prompt or skill edit needed. Crate-gated subsections (`## Tracing` — "for projects using the `tracing` crate") scope rules below the language level; reuse that pattern rather than splitting files per crate.

`/shipit` is the Greater Arc: a compression of negentropy'd Major Arcs into one commit on a PR branch named `<kebab-identity>/pr/<feature-tag>`. It refuses to run if CHECKPOINT commits remain in `origin/main..HEAD`. Identity is kebab-cased at runtime from `git config user.name`. It is stack-aware: a pending PR whose commits are all patch-contained in local history (`git cherry`) becomes the base, and `gh stack link` registers the chain. Post-ship, the original branch adopts the PR branch's history, so it reads main + pending stack + one crystallized commit, and squash-merged PRs drop from it by patch-id on rebase.

See [docs/shell-style.md](docs/shell-style.md) for `writeShellApplication` discipline.

Open items:

- **Stack flow untested**: `/shipit` stack detection (`git cherry` containment), `gh stack link` registration, and the Phase 7 reset-sync have not run against a real stacked PR. Exercise on the next multi-PR feature.
- **Plugin namespace collisions**: every self-invocation in `prompts/arcs.md` and the skill bodies uses the `arcs:` prefix, so the model never resolves a bare name. A user typing bare `/checkpoint` while a user-scope skill of that name exists hits undocumented resolution order; whether bare plugin names resolve in the TUI at all is unverified.
- **Color tuning**: brand purple `#B388FF` is approximate — verify against Claude Code TUI source if possible.
- **System flake integration**: remote invocation via `nix run github:bugeats/claude --refresh` is the primary path. Inclusion in a system flake via `packages.default` is untested.
- **Permission rule semantics**: `Bash(nix:*)` colon syntax matches `nix` subcommands but not hyphenated binaries like `nix-prefetch-github`.
- **rust-analyzer is a removal candidate**: the plugin registers it unconditionally, no prompt guidance references it, and Chadwick has never observed the model reach for it. If that holds, drop the MCP config, its flake inputs, and the `docs/dependencies.md` entry together.
- **rustfmt edition hardcode**: the format hook passes `--edition 2024` (standalone rustfmt otherwise defaults to 2015 and rejects `async fn`). Legacy 2015-edition crates using `async`/`try`/`dyn` as identifiers would fail to parse; if that ever bites, read the edition from the nearest `Cargo.toml` instead.

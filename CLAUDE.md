# Claude Arcs

Nix flake that ships Claude Code workflow as a **plugin**, launched remotely with `nix run github:bugeats/claude --refresh`. The default package is a one-line launcher over the built plugin derivation (`packages.plugin`); the launcher writes nothing to `~/.claude/`. Mechanics and unmanaged state: [docs/launcher.md](docs/launcher.md). Runtime inputs: [docs/dependencies.md](docs/dependencies.md). Shell discipline: [docs/shell-style.md](docs/shell-style.md).

This is a shared distribution used by teammates and a growing circle of users. Changes here affect everyone on next launch.

**Everything the plugin says to the model is opt-in.** Guidance ships as two output styles selected in `/config`: `arcs:manual` carries the Compression Principle, the working contract, and context guidance; `arcs:auto` adds the arc workflow and its automatic triggers. With no style selected the session is vanilla Claude Code with the arcs skills available but never self-invoked. Claude Code keys plugin styles as `<plugin>:<name>`, so every self-invocation in `prompts/` and the skill bodies uses the `arcs:` prefix.

This file is project instructions for *this repo only*. The shipped prose lives in `prompts/`, and tightening it is fair game at any checkpoint.

## Architecture

```
flake.nix                    # packages.plugin builds the plugin dir; default = claude-arcs launcher
.claude-plugin/plugin.json   # plugin manifest
hooks/hooks.json             # hook registrations (paths via ${CLAUDE_PLUGIN_ROOT})
settings.json                # passed via --settings; statusLine path baked at build
prompts/{containment,arcs}.md  # style bodies; spliced into output-styles/{manual,auto}.md at build
skills/<name>/SKILL.md       # auto-discovered by the plugin loader
style/<lang>.md              # language review criteria, read during /checkpoint Step 1
hooks/*.sh tools/*.sh        # writeShellApplication bodies
statusline.py                # invoked from settings.json; shebang patched at build
```

`.mcp.json` (rust-analyzer) is generated by the flake, not checked in: a source-tree copy would load as a project-scope server in every session developing this repo.

## Usage

Validate plugin changes locally (the plugin is the built derivation, not the source tree):

```
nix build .#plugin
claude plugin validate result
claude --plugin-dir result plugin details arcs
```

`/nix` wraps build, run, and status for the project flake and carries the flake conventions.

## Design Decisions

Three arcs ship: `/checkpoint` (Minor), `/negentropy` (Major), `/shipit` (Greater). `/negentropy` owns a runtime-entropy lens in-tree rather than delegating to `/simplify`, since fanning out three review agents per minor arc would discourage frequent checkpoints.

Language-specific style is tiered by cost-of-late-detection: mechanical rules → PostToolUse hooks (edit time); surface judgment → `style/<lang>.md` read at arc close, deliberately withheld from generation time because review compliance beats generation compliance; structural rules → Universal Code Style in `prompts/containment.md`, which must stay tiny. Add a language by dropping a file into `style/`. Crate-gated subsections (see `## Tracing` in `style/rust.md`) scope rules below the language level; reuse that pattern rather than splitting files per crate.

The statusline gauge and the `/negentropy` rebase share `tools/checkpoint-range.sh` so they never disagree about the range. `statusline.py` always exits 0 and logs tracebacks to `~/.claude/statusline.log`, because Claude Code suppresses the status line after repeated failures.

## Current Focus

**OPTN — opt-in via output styles.** Interactive and headless selection are confirmed.

- **OPTN-5** Mid-session style switching: an `outputStyle` settings change does not rebuild the system prompt within a turn. Whether it applies on the next user turn or only after `/clear` is unknown; record the answer in docs/launcher.md once observed.

Still unverified on a fresh `nix run --refresh`: statusline rendering and skill resolution under `${CLAUDE_PLUGIN_ROOT}`.

## Open Items

- **Stack flow untested**: `/shipit` stack detection, `gh stack link`, and the post-ship reset-sync have not run against a real stacked PR.
- **Bare skill names**: whether `/checkpoint` resolves to the plugin skill in the TUI, and what wins when a user-scope skill shares the name, is unverified.
- **rust-analyzer is a removal candidate**: registered unconditionally, referenced by no guidance, never observed in use. Drop the MCP config, its flake inputs, and the `docs/dependencies.md` entry together.
- **Permission rule semantics**: `Bash(nix:*)` matches `nix` subcommands but not hyphenated binaries like `nix-prefetch-github`.
- **System flake integration**: consuming `packages.default` from another flake is untested.
- **Color tuning**: brand purple `#B388FF` is approximate; verify against Claude Code TUI source if possible.
